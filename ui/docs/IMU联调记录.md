## 本轮 UI 修改与验证

- 明确选择 USB 或蓝牙 SPP，取消自动复用第一个 CH340 和固定 COM8 文案。
- 蓝牙 SPP 使用标准服务 UUID `00001101-0000-1000-8000-00805f9b34fb`，要求事先在 Windows 中配对，并输出相同的 31 字段 CSV。它不是已验证的手套协议，不支持未知 BLE GATT 服务。
- 串流解析拒绝空字段、非有限数值、错误字段数、越界电压及超出约 ±π 的姿态弧度。增加未换行缓冲区上限。
- 三轴实物读数显示 ±180°；全零时提示无法区分静止零位与 IMU 未收到数据；断流时标示最后一次数据。
- 建立连接后未收到有效帧也会进入断流状态，重新收到有效帧后恢复。读取结束释放端口，切换教学模式时断开实物设备。
- TypeScript/Vite 构建通过；有效帧、少字段、空字段、角度单位越界和 NaN 五项解析检查通过；浏览器检查两个连接入口和等待姿态状态均正常。
- 修改前备份：`D:\cupet\maintenance\imu-before-20261114`。

## 尚需实物确认

1. 开启手套电源，在 Windows 蓝牙设置中搜索，记录手套设备名称及是否能配对。论文没有给出设备名、PIN、SPP/BLE 类型或服务 UUID。
2. 确认 COM21 对应硬板还是手套；仅接 USB 可能只是供电，不能等同于 IMU 已连接。
3. SPP 配对后，进入实验台 → 实物 USB / 蓝牙 → 连接蓝牙手套，由用户在浏览器选择实际设备。若是 BLE，必须先确认真实服务、特征 UUID 和数据格式。
4. 分别俯仰、左右偏航、横滚，验证三个角度变化及模型方向。现有三维模型轴映射尚未通过实物验证，不能把页面变化当作传感成功。
5. 若设备确实运行本地 USB 复现固件，需要先核实 JY60 的供电、UART 接线和有效输出，再评估蓝牙固件改动；本轮未刷写。

参考：[Chrome 官方蓝牙串口说明](https://developer.chrome.com/blog/serial-over-bluetooth/)。

## 断开硬板后的重要更正

用户确认只保留手套 USB 后，pyserial 枚举结果为空，Windows 当前设备列表也没有 Ports 类或 CH340K。之前 COM21 随硬板断开而消失，说明先前 260 帧更可能来自硬板，不能用它们证明手套 IMU 输出为零。该归属还需逐块插拔验证。

柔性板工程包含 CH340K（U32）与 Type-C（USB2），因此应先恢复手套的 USB 枚举，再进行 IMU 原始数据采样。已请用户用硬板已验证的数据线和同一电脑接口连接手套；未刷写任何固件。
