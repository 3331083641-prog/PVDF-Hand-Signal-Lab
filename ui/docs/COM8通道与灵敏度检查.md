# COM8 通道与灵敏度检查

检查日期：2026-08-23 至 2026-08-25

## 结论

本次复核确认了四个独立问题：

1. ESP32 固件的 `acquire28Channels()` 已把同一 ADC 引脚的 LOW/HIGH bank 交错写入 `output[2*i]` 与 `output[2*i+1]`，官方 `HSAD_PC_COM8.py` 也明确使用 `raw28[0::2]` 和 `raw28[1::2]`。网页此前又按硬板网络重排一次，反而把不同传感器错误配成一对。
2. ESP32 固件已经对 28 路电压执行二阶 6 Hz 数字低通，网页再次滤波会削弱、延迟短促压电脉冲。
3. 固定 6 mV 积分阈值低于当前硬件部分通道的静止噪声；旧零漂跟踪又会在残差超过 8 mV 后停止，导致静止状态误积分并饱和到 90°。
4. 未标定串口曾直接使用约 160 °/(V·s) 的教学模拟增益；对几十毫伏、持续数百毫秒的实测压电脉冲只能产生约 1° 量级变化，表现为整只手迟钝。

网页现已恢复固件真实的相邻字段配对、取消浏览器重复滤波，并采用每个物理信号源静止噪声的稳健估计生成 2.5–10 mV 自适应阈值。触发采用启停滞回和短保持，可捕捉弱脉冲而不被单点抖动反复开关。未完成0°→90°实测标定时，使用按噪声门限计算的 1400–4500 °/(V·s) 预标定增益；完成标定后始终以该关节真实增益为准。

连接或重校零点时应保持手掌张开。每个未标定关节第一次超过极性判定门限的有效脉冲自动定义为“弯曲”方向，使正反两种贴装/接线极性都能产生虚拟手动作；若首次动作不是弯曲，可用界面的“反向极性”修正。

- 串口：USB-SERIAL CH340K（COM8）
- 波特率：460800
- 帧格式：28 路电压 + Pitch/Yaw/Roll，共 31 字段
- 实测刷新率：约 79.9–80.1 Hz
- 新浏览器会话控制台：0 error
- 2026-08-25 最终复核时 Windows 未枚举到 COM8，因此本轮完成了固件/上位机/前端三方代码交叉验证和浏览器构建验证，仍需设备重新插入后完成14路动作复测。

## 通道异常记录

早期巡检曾把 CH3 按错误重排解释为中指 DIP；根据固件相邻输出规则，CH3 实际属于 D2 的第一路，原异常归属无效，不再据此判断中指硬件故障。设备重新插入后若任一原始通道持续接近0 V或3.3 V，再按网页当前显示的相邻通道号检查对应传感器、连接器、TMUX输入和调理输出。

网页已增加接近 0 V 或 3.3 V 的原始通道告警。该告警只能发现明显饱和/断路，不能替代示波器和万用表检查。

## 仍需完成的实物标定

硬板 EDA 可以确定 28 路电气配对，但不能仅靠静止数据验证实际 FPC、连接器和装配后的源顺序是否仍对应预期解剖关节。网页已加入“识别当前实物关节”：

1. 选择一个虚拟关节；
2. 点击“识别当前实物关节”；
3. 固定其他关节，只连续弯曲该实物关节 3 次；
4. 点击“完成识别”；
5. 系统比较全部 14 组差分源的去噪能量和峰值，把最显著源与目标骨骼绑定；
6. 若该源已被另一关节占用，系统执行一对一交换，避免同一路信号同时驱动两个骨骼；
7. 绑定完成后再进行该关节的 `0°→90°` 角度标定。

建议先验证中指、无名指、小指各关节，再检查拇指与食指。映射结果与极性、角度增益持久化保存在当前浏览器本地；没有完成角度标定的关节使用自适应预标定增益，能提供清晰动作反馈，但仍不能视为实测角度标定结果。
